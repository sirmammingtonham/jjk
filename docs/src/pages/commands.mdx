# Command reference

`jjk` speaks familiar git commands. Run `jjk <command> --help` for flags.

## Repo setup

| Command | What it does |
| --- | --- |
| `jjk repo init` | Initialize a colocated jj+git repo here; detect & store trunk and remote. |

## Local work

| Command | What it does |
| --- | --- |
| `jjk commit -m <msg>` | Commit changes. If files are **staged in git** (e.g. from your editor), commits just those; otherwise commits the whole working copy. Runs the git `pre-commit` hook (`-n`/`--no-verify` to skip). Mid-stack commits auto-restack the upstack. |
| `jjk commit -m <msg> <paths...>` | Commit only the given paths; the rest stays uncommitted. |
| `jjk commit -i -m <msg>` | Interactively pick hunks/files to commit (diff editor); the rest stays uncommitted. |
| `jjk commit --amend [-m <msg>]` | Amend the current branch's tip; descendants auto-rebase. |
| `jjk commit --fixup <branch>` | Fold the working-copy changes into `<branch>`'s tip (an older commit downstack); descendants auto-rebase. |
| `jjk commit --split` | Split the branch tip into two commits (interactive diff editor). |
| `jjk commit --pick <rev>` | Copy a commit (e.g. from an upstack branch) onto the current branch. |
| `jjk checkout -b <name>` | Create a new **untracked** branch on top of the current one. |
| `jjk checkout <name>` | Switch to an existing branch (always safe; never errors on uncommitted work). |
| `jjk status` | Working-copy status plus your position in the stack. |
| `jjk ls` | Stack diagram (branches only). |
| `jjk ll` | Stack diagram with each branch's commits. |
| `jjk stash` / `jjk stash pop` | Park / restore working-copy changes (mostly unnecessary, since switching is safe in jj). |
| `jjk add` | Friendly reminder that jjk has no staging area of its own but honors git's (`git add` then `jjk commit`). |

## Stack management

| Command | What it does |
| --- | --- |
| `jjk branch create [name]` | Create a new **tracked** branch (a PR) stacked on the current one. |
| `jjk branch delete <name>` | Delete a branch and heal the gap, so the upstack reconnects to its parent. |
| `jjk branch onto <target>` | Move the current branch (and everything above it) onto a new base. |
| `jjk branch rename [old] <new>` | Rename a branch (default: the current one), keeping its PR mapping. |
| `jjk branch diff` | Show the current branch's diff against its base. |
| `jjk branch squash [-m <msg>]` | Collapse all of the current branch's commits into one. |
| `jjk branch fold` | Fold the current branch into its downstack base (one fewer PR). |
| `jjk branch split <new> <commit>` | Split the current branch at `<commit>` into two branches (`<new>` takes the lower commits). |
| `jjk track [name]` / `jjk untrack [name]` | Toggle whether a branch is part of the stack / gets a PR. Defaults to the current branch. |
| `jjk restack` | Re-parent the upstack onto its bases. Usually a no-op (jj auto-rebases). |
| `jjk up` / `jjk down` | Move one branch away from / toward trunk. |
| `jjk top` / `jjk bottom` / `jjk trunk` | Jump to the top / bottom of the stack, or to trunk. |
| `jjk resolve` | Open the lowest conflicted change for editing; the fix propagates upstack. |
| `jjk undo` | Undo the last `jjk` command as a single unit (it may be several jj operations), restoring both the repo and jjk's state. Run repeatedly to walk further back. |

## Remote & forge (GitHub)

| Command | What it does |
| --- | --- |
| `jjk fetch` | Fetch from the remote. |
| `jjk pull` | Fetch trunk and rebase the current stack onto it (no merged-PR detection, no push). |
| `jjk push` | Push the current branch (force-with-lease). |
| `jjk pr view` | Open the current branch's PR in the browser. `--print`/`-p` prints the URL instead (for scripts / headless use). |
| `jjk submit` | Push the whole stack and create/update a PR per branch, each based on the one below it. For each **new** branch it prompts for the PR title, body, and draft status (title defaults to the commit subject; press `e` at the body prompt to edit in `$EDITOR`). Branches that already have a PR are updated without prompting. Idempotent; updates the stack-navigation comment. |
| `jjk branch submit` | Submit just the current branch's PR. |
| `jjk upstack submit` / `jjk downstack submit` | Submit only the current branch and everything above / below it. Bases still point at each branch's real downstack branch. |
| `jjk submit --fill` | Don't prompt — fill new PRs' title/body from the commit messages. (Also implied when stdout isn't a terminal, e.g. CI.) |
| `jjk submit --draft` | Open newly-created PRs as drafts. Pre-selects the draft prompt; has no effect on PRs that already exist. |
| `jjk sync` | Fetch, reconcile merged PRs, rebase survivors onto trunk, force-push, and retarget PR bases. Handles squash- and merge-commit landings. |
| `jjk sync -n` / `--no-push` | Reconcile local state only (fetch, drop merged branches, rebase onto trunk). Doesn't push branches or retarget PRs. Faster, and safe when you're not ready to touch the remote. |

## Worktrees (parallel workspaces)

| Command | What it does |
| --- | --- |
| `jjk worktree add <path> [name] [--branch <b>]` | Add a [jj workspace](https://jj-vcs.github.io/jj/latest/working-copy/#workspaces), optionally started on a branch. |
| `jjk worktree list` | List workspaces and each one's current branch. |
| `jjk worktree remove <name>` | Stop tracking a workspace (files are left on disk). |

The current branch is tracked **per workspace**; stale working copies are recovered automatically.
